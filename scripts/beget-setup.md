# Настройка Beget для нового сайта

Разовый чек-лист на аккаунт клиента (или общий, если хостинг остаётся на
обслуживании у Лены — см. решение 7 в плане). Выполняет Лена, агент может
подсказывать команды и проверять результат по URL.

## 1. Тариф и домен

1. Тариф **Blog** (~420 ₽/мес, до 5 сайтов) — этого достаточно для одного
   лендинга с панелью.
2. Привязать домен клиента (или завести поддомен, если домена ещё нет).
3. Включить бесплатный SSL (Let's Encrypt) в панели Beget для домена —
   без него браузер клиента будет ругаться на сайт и не даст войти в панель
   (cookie сессии ставится с `secure` в проде, см. `panel/session.js`).

## 2. Поддержка Node.js — проверить в первую очередь

Решение 1 плана предполагает Node.js на виртуальном хостинге Beget.
**Перед тем как писать что-то ещё, проверить**:

1. В панели Beget → раздел «Node.js» (или «Приложения») — доступен ли он
   на выбранном тарифе.
2. Если недоступен на Blog — сравнить с тарифом выше или уточнить в
   поддержке Beget, на каком тарифе Node.js есть. Это может поменять
   стоимость из решения 7 — обновить план, если так.
3. Зафиксировать здесь версию Node, которую даёт панель Beget (нужна 20.x —
   как в остальном проекте).

## 3. Структура папок на сервере

```
/сайт.ру/public_html/          ← корень сайта, сюда FTP-робот кладёт _site/
/сайт.ру/public_html/admin/    ← статика Sveltia (часть _site/, тот же деплой)
/сайт.ру/panel/                ← Node-приложение panel/ — ВНЕ public_html
/сайт.ру/panel/store/          ← config.json, users.json — вне веб-корня и вне git
```

`panel/store/*.json` не должны быть доступны по прямой ссылке ни при каких
обстоятельствах — поэтому вся папка `panel/` кладётся выше `public_html`,
а наружу торчит только то, что настроено в шаге 5 (`/admin/_panel/*`).

## 4. Завести Node-приложение

1. В панели Beget → Node.js → создать приложение:
   - точка входа: `panel/server.js`;
   - рабочая директория: `/сайт.ру/panel/`;
   - переменные окружения: `PORT` (даёт Beget), `NODE_ENV=production`.
2. Загрузить содержимое `panel/` (код, `package.json`) на сервер (SFTP/git —
   что доступно на тарифе) и выполнить `npm ci --omit=dev` в рабочей
   директории.
3. Скопировать `panel/store/config.example.json` → `panel/store/config.json`
   и `users.example.json` → `users.json`, заполнить реальными значениями
   (репозиторий, токен бота, `sessionSecret` — случайная строка от 32
   символов, ссылка на поддержку). **Не коммитить эти файлы** — они и так
   в `.gitignore`, но проверить, что на сервере они не лежат внутри
   `public_html`.
4. Создать первого пользователя-владельца:
   `node -e "import('./users.js').then(u => u.createUser('./store/users.json', {email: 'ПОЧТА_КЛИЕНТА', role: 'owner'}).then(r => console.log(r.tempPassword)))"`
   — временный пароль вывести на экран и передать клиенту отдельно (не в
   письме вместе с логином).

## 5. Прокинуть `/admin/_panel/` на Node-приложение

Beget обычно делает это через настройку прокси/маршрута приложения Node.js
на конкретный префикс URL (детали — в интерфейсе конкретного тарифа,
уточнить при первом заведении и дописать сюда точные шаги/скриншоты).
Цель: запросы на `https://сайт.ру/admin/_panel/*` должны доходить до
`panel/server.js`, а `https://сайт.ру/admin/*` (без `_panel`) и всё
остальное — отдаваться статикой из `public_html`.

## 6. Проверка (Задача 3.2 — «зелёная проверка»)

- `https://сайт.ру/admin/_panel/health` → `200 {"status":"ok","repo":"..."}`.
- `https://сайт.ру/admin/` → отдаёт панель Sveltia (статика).
- `https://сайт.ру/` → отдаёт собранный сайт-заглушку.

Если что-то не совпало — сверить шаг 5 (маршрутизация) и переменные
окружения Node-приложения.

## 7. Подключить робота (после того как 1–6 пройдены)

Прописать секреты `BEGET_FTP_HOST/USER/PASSWORD/PATH` в GitHub (см.
`scripts/deploy-notes.md`) — `BEGET_FTP_PATH` указывает на `public_html/`
из шага 3, не на всю учётную запись.
