# Чек-лист: новый сайт клиенту

Разовые шаги при заведении сайта на этом шаблоне. Часть делает Лена сама,
часть — агент по её команде. Отмечено где что.

## 1. Заготовка кода

- [ ] Скопировать (форкнуть) этот репозиторий как основу для нового сайта
      клиента — **пока без пуша куда-либо**, работать локально до шага 4.
- [ ] Убрать тестовый контент-пример: `src/content/services/*`,
      `src/content/faq/*` — оставить как образец структуры или удалить,
      в зависимости от того, есть ли готовые тексты клиента.

## 2. Схема полей и вёрстка (агент + Лена)

- [ ] Переписать `src/admin/config.yml` под блоки конкретного сайта —
      единственный файл, где описан «список полей». Ориентир — типы полей
      и структура уже показаны на примере (`hero`, `contacts`, `settings`,
      `prices`, `seo`, `services`, `faq`).
- [ ] Собрать вёрстку под бренд клиента (цвета, шрифты, структура секций) —
      обсудить с Леной, реализует агент. Наполнить `src/_data/*.json` и
      `src/content/**` реальными (или заглушечными на старте) текстами.
- [ ] Логотип клиента → `src/admin/branding/logo.png`; поправить `app_title`,
      `site_url`, `display_url` в `config.yml`.
- [ ] `npm run check:config && npm run build` — обе команды зелёные.

## 3. GitHub — репозиторий клиента (Лена)

- [ ] Создать **новый пустой репозиторий на аккаунте клиента** (не на
      аккаунте Лены/студии) — независимость с первого дня, решение 3 плана.
- [ ] Добавить бот-аккаунт студии соавтором репозитория (роль, дающая
      писать в контент и открывать PR — обычно `Write`).
- [ ] От имени бота выпустить **fine-grained personal access token**:
      Settings → Developer settings → Fine-grained tokens → New token →
      Resource owner — аккаунт клиента → Only select repositories — этот
      репозиторий → Permissions: **Contents: Read and write**,
      **Pull requests: Read and write**. Срок — 1 год (решение 4 плана,
      продление по напоминанию).
- [ ] Запушить код заготовки в этот репозиторий (ветка `main`).

## 4. Beget — хостинг (Лена, чек-лист `scripts/beget-setup.md`)

- [ ] Пройти `scripts/beget-setup.md` целиком: тариф, домен, SSL, проверка
      поддержки Node.js, структура папок, Node-приложение `panel/`.
- [ ] `panel/store/config.json` на сервере: `repo` (owner/repo клиента),
      `botToken` (из шага 3), `sessionSecret` (случайная строка от 32
      символов), `supportUrl`.
- [ ] Проверка: `/admin/_panel/health` отвечает `200`.

## 5. Секреты робота (Лена)

- [ ] В репозитории клиента — Settings → Secrets and variables → Actions:
      `BEGET_FTP_HOST`, `BEGET_FTP_USER`, `BEGET_FTP_PASSWORD`,
      `BEGET_FTP_PATH` (см. `scripts/deploy-notes.md`).
- [ ] Пустой коммит или правка в `main` → проверить, что робот прошёл
      зелёным (вкладка Actions) и сайт обновился.

## 6. Первый пользователь (Лена или агент по её команде)

- [ ] На сервере (там, где лежит `panel/store/users.json`):
      ```
      node -e "import('./users.js').then(u => u.createUser('./store/users.json', {email: 'ПОЧТА_КЛИЕНТА', role: 'owner'}).then(r => console.log(r.tempPassword)))"
      ```
- [ ] Временный пароль передать клиенту **отдельным каналом** от логина
      (например логин в одном сообщении, пароль — в другом или голосом).

## 7. Сдача клиенту

- [ ] Пройти весь цикл самостоятельно: войти на `/admin/`, поправить поле,
      «Опубликовать», убедиться что сайт обновился (~1 минута).
- [ ] Комплект сдачи — `docs/handover/` (чек-лист приёмки, границы
      поддержки, план обучающих видео) — Задача 5.3, пока не готов.
