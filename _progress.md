## Проверено автотестами (headless-симуляция в Node, без реального браузера)

- Все 7 кнопок ниш ведут на правильный следующий экран (симуляция кликов).
- Полный проход ветки «Салон» до результата с aiPartner=true → шкала скрыта, текст заменён на AI-агент.
- Полный проход с ответами «справляюсь» везде → 0%, нейтральный текст, кросс-сейла нет.
- outbound-ветка → категория site показывается как «База», aiPartner=maybe → мягкая приписка показана.
- customInbound-ветка → кросс-сейл по второй категории показывается корректно.
- Валидация формы: невалидный контакт / нет согласия — fetch не вызывается; валидная отправка — ровно один запрос на Apps Script с полным расширенным payload (name, contact, tariff, message, niche, flow, quiz_answers, result_category, result_percent, ai_partner).

## Не проверено (нет интерактивного браузерного инструмента в этой сессии)

- Визуально в реальном браузере — Лена тестирует сама, я проверяла логикой через Node-símуляцию DOM.
- Мобильная раскладка <768px — визуально не проверено, только сам факт наличия правильного медиа-запроса.

## Заметки

- Все 9 наборов веток и Q5 переносятся из спека дословно (текст и веса не менять).
- theoreticalMax считаю один раз при старте ветки как сумму весов всех опций вопроса по категории (не завиcит от ответов) — так проще и надёжнее чем инкрементально.
- totals для результата считаю один раз в computeResult из state.answers на момент показа результата (не аккумулирую на каждый next) — чтобы «Назад» не приводил к двойному счёту.
- outbound-ветка: категория `site` отображается как «База» через categoryLabelOverrides.
