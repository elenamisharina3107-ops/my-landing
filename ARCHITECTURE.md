# Как устроено и план первой версии

Черновик от 2026-09-01. Продолжение `CONCEPT.md`. Технические решения приняты агентом,
как договорились. Верхний раздел — простым языком, ниже — детали для разработки.

---

## Простым языком

**Из чего состоит один сайт с панелью:**

- сама страница сайта (её видят посетители);
- панель по адресу `сайт.ру/admin` (туда заходит клиент с логином и паролем);
- «память» проекта — где хранятся все тексты, цены и загруженные картинки;
- история версий — каждое «Сохранить» запоминается, можно откатиться назад.

Всё это — **один проект на Vercel**, заведённый на аккаунт клиента. Домен с Beget тоже на
клиента. Отдельного сервера, отдельной подписки, ничего «у Лены» в работающем сайте нет.

**Как делается новый сайт (по шагам, каждый раз одинаково):**

1. Взять заготовку (общий шаблон, который мы сейчас и строим).
2. Прописать список того, что клиент сможет менять на этом сайте (тексты, цены, блоки).
3. Собрать внешний вид страницы (это ты делаешь со мной, как обычно).
4. Завести клиенту проект на Vercel и домен, подключить «память» проекта.
5. Залить начальные тексты, создать клиенту логин, отдать доступ.

После готовой заготовки шаги 4–5 — это минуты, шаг 2 — несколько минут, основное время —
шаг 3 (внешний вид), как и сейчас.

**Что клиент делает в панели:** меняет текст, цену, картинку, пункты списка (услуги,
отзывы, вопросы-ответы) → «Сохранить» → сайт сразу обновился. Ошибся — открыл «Историю»,
вернул прошлую версию одной кнопкой.

## Технические решения

### Стек

| Слой | Выбор | Почему |
|---|---|---|
| Каркас сайта и панели | **Next.js (App Router)** на Vercel | контент должен быть в странице сразу при загрузке (поиск, никакого мигания «рыбы»); панели нужен бэкенд (вход, сохранение, загрузка файлов); Vercel запускает Next.js без настройки — сайт и панель в одном проекте |
| База данных | **Postgres (Neon через Vercel Marketplace)** | бесплатного тарифа с запасом хватает на контент лендинга; теснее всего интегрирован с Vercel |
| Хранение картинок | **Vercel Blob** | загрузка из панели → готовый URL → URL кладётся в контент |
| Вход и роли | **Auth.js (NextAuth), провайдер Credentials** (email + пароль) | стандарт для Next.js, сессии в БД, две роли (см. раздел «Роли») |
| Описание полей сайта | файл **`content.schema.json`** в репозитории | панель рисует форму по нему; компоненты сайта читают контент по ключам из него |

Рассматривались альтернативы: хранить контент в git-репозитории и пересобирать сайт на
каждое сохранение (Decap-подход) — отклонено из-за задержки пересборки и лишней возни с
токенами; SQLite/Turso вместо Postgres — рабочий вариант, но Neon чище ложится на Vercel.

### Модель данных (Postgres)

- `content_current` — текущий контент сайта, одна строка, поле `data jsonb`.
- `content_versions` — по строке на каждое сохранение: `data jsonb`, `author_id`,
  `created_at`, `note`. Откат = копирование строки в `content_current`.
- `users` — `email`, `password_hash`, `role` (`owner` | `editor`), `must_change_password`.
- `sessions` — стандартные для Auth.js.

Медиа: файлы в Vercel Blob, в контенте хранится только URL. Список загруженных файлов —
из Blob API, отдельная таблица не нужна.

### Формат `content.schema.json`

Описывает разделы и поля. Пример:

```json
{
  "sections": [
    {
      "id": "hero",
      "title": "Первый экран",
      "fields": [
        { "key": "hero.title", "type": "text", "label": "Заголовок",
          "hint": "Главная фраза, которую видят сразу" },
        { "key": "hero.subtitle", "type": "longtext", "label": "Подзаголовок" },
        { "key": "hero.image", "type": "image", "label": "Фон/картинка" }
      ]
    },
    {
      "id": "prices",
      "title": "Цены",
      "fields": [
        { "key": "prices", "type": "list", "label": "Тарифы",
          "item": [
            { "key": "name", "type": "text", "label": "Название" },
            { "key": "price", "type": "number", "label": "Цена, ₽" },
            { "key": "old_price", "type": "number", "label": "Старая цена, ₽" }
          ] }
      ]
    }
  ]
}
```

Типы полей в первой версии: `text`, `longtext` (с базовым форматированием — жирный,
ссылки, списки), `number`, `image`, `url`, `boolean`, `list` (повторяющаяся группа полей).

### Как сайт читает контент

Компоненты страницы берут значения через типовой помощник по ключу из схемы
(`content("hero.title")`). Рендер — на сервере Vercel, поэтому в HTML сразу правильный
текст. После сохранения в панели страница обновляется без пересборки (сброс кэша по метке).

### Роли

Обе роли редактируют **весь** контент сайта одинаково — тексты, цены, картинки, списки,
SEO-поля. Разница только в управлении доступом:

- `owner` (клиент) — плюс к контенту: заводит и удаляет пользователей, меняет настройки
  проекта. Не может быть заблокирован (единственный владелец удаляется только заменой).
- `editor` — только контент, без управления людьми и настройками. Эту роль обычно
  получает Лена на обслуживании, чтобы работать со своим логином, не зная пароля клиента
  и не имея возможности отобрать у клиента доступ.

Смысл разделения: клиент всегда остаётся хозяином — сам решает, кто ещё может править сайт,
и его нельзя случайно или намеренно выкинуть. Если клиенту это не нужно — можно выдавать
всем `owner`, роль `editor` просто не использовать.

Первый вход — по временному паролю, принудительная смена.

### Что отдаётся клиенту при сдаче

Аккаунты Vercel, Neon, Blob, домен Beget, репозиторий с кодом — всё заведено на клиента.
Логин `owner` — клиенту. Чек-лист передачи — в отдельном файле при готовности шаблона.

## План первой версии

Делаем по методике TDD там, где есть логика (помощники, схема, вход, откат версий).

### Этап 0 — Каркас

- [ ] Next.js-проект, деплой на Vercel, подключены Neon и Blob.
- [ ] Формат `content.schema.json` + загрузчик с проверкой корректности.
- [ ] Таблицы `content_current` / `content_versions`; помощники чтения и записи контента.
- [ ] Auth.js: вход, сессия, две роли, создание первого `owner`, смена пароля.

### Этап 1 — Панель

- [ ] Форма по схеме: разделы, подписи, подсказки, проверка ввода.
- [ ] Все типы полей, включая `list` (добавить/удалить/переставить пункт).
- [ ] Загрузка картинок в Blob прямо из формы.
- [ ] «Сохранить» → новая версия; экран «История» + «Вернуть эту версию».
- [ ] Удобство: черновик в браузере (не потерять при закрытии вкладки), предупреждение о
      несохранённых правках, понятные состояния «сохранено / сохраняю / ошибка».

### Этап 2 — Сторона сайта

- [ ] Помощник чтения контента по ключам схемы, обновление страницы после сохранения.
- [ ] Поля SEO (заголовок вкладки, описание, картинка для соцсетей) в схеме.
- [ ] Пример лендинга, собранный на этом шаблоне.

### Этап 3 — Превращение в шаблон

- [ ] Скрипт/чек-лист «новый сайт»: копия заготовки → заполнить схему → завести проекты →
      залить контент → создать клиента.
- [ ] README для Лены (как собрать новый сайт).
- [ ] Чек-лист передачи аккаунтов клиенту.

### Этап 4 — Боевая проверка

- [ ] Один реальный сайт полностью на этом шаблоне.
- [ ] Проверен весь цикл: вход → правка каждого типа поля → сохранение → сайт обновился →
      откат работает → смена пароля работает.

### Не в первой версии (следующее)

Режим «черновик → предпросмотр → публикация» (сейчас сохранение сразу публикуется, но есть
откат) — **первый кандидат на v1.1**. Дальше: сжатие картинок, несколько языков, права по
разделам, редактор промпта ИИ-сотрудника отдельным модулем.

## Открытые технические вопросы (решает агент по ходу)

- Точный набор форматирования в `longtext` (минимум: жирный, ссылка, маркированный список).
- Библиотека формы и rich-text (кандидаты: react-hook-form + Tiptap).
- Нужен ли отдельный поддомен `admin.сайт.ру` или хватит пути `/admin` (склоняюсь к `/admin`).
- Как именно сбрасывать кэш страницы Vercel после сохранения (тег ревалидации).
