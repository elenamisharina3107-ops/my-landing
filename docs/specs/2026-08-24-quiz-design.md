# Квиз для лидогенерации Vireflow — дизайн

**Дата:** 2026-08-24
**Статус:** на ревью у Лены

## Зачем

Лид-магнит на сайте vireflow.ru: короткая анкета про бизнес клиента → персональная рекомендация (сайт / бот / AI-агент / комплексная автоматизация) → заявка. Три цели одновременно:

1. Выявляет реальную боль клиента ещё до звонка.
2. Демонстрирует экспертность — рекомендация выглядит как разбор, а не рекламный текст.
3. Сам квиз — живой кейс собственного продукта («квалификация лидов», которую Vireflow продаёт клиентам) в портфолио.

Технически — свой код (HTML/JS/CSS), без сторонних конструкторов. Отдельная страница `vireflow.ru/quiz`, чтобы можно было давать прямую ссылку из постов ВК, объявлений Авито и рекламы, не трогая главную.

**Тон обращения:** квиз обращается к проходящему его человеку на «Вы» — это вежливая форма для незнакомого посетителя сайта, а не разговорная. Все формулировки вопросов ниже уже приведены в этой форме.

## Поток целиком

```
Экран 0: выбор сферы
  → 7 кнопок ниш (Предприниматель / Салон / Стоматология / HR / Бухгалтер / Оценщик / Юрист)
  → + поле «Своё» (свободный текст)

Если ниша = Предприниматель ИЛИ Своё:
  → доп. экран-развилка: «Есть готовый поток обращений, или сами ищете клиентов?»
     → Входящие  → нишевая/generic ветка (входящая версия)
     → Исходящие → аутбаунд-ветка

Остальные 5 ниш (Салон, Стоматология, HR, Бухгалтер, Оценщик, Юрист):
  → сразу нишевая ветка (входящая версия, развилки нет — это услуги
    для конечных клиентов с естественным входящим потоком)

Ветка = 4 вопроса (Q1..Q4), каждый — чекбоксы (можно отметить несколько)
  → в конце ветки: Q5, общий для ВСЕХ веток без исключений («AI-партнёр»)

Экран результата:
  → шкала % + текст по категории-победителю
  → строка кросс-сейла по второй категории
  → если отмечен Q5 «Да» — текст и CTA заменяются на AI-партнёр-вариант

Форма контакта → тот же pipeline, что на главной странице (Formspree + Google Script)
```

## Категории и подсчёт баллов

Четыре категории на всех входящих ветках: **Сайт / Бот / Агент / Команда**. На аутбаунд-ветке те же четыре категории переосмыслены под исходящие продажи: **База (аналог Сайта) / Бот / Агент / Команда**.

Правила:

- **Все вопросы без исключения — чекбоксы с множественным выбором**, это касается каждого Q1–Q4 во всех 8 ветках и общего Q5, а не только вопросов вида «что отнимает время». На экране каждого вопроса под заголовком показывается подсказка **«Отметьте всё, что подходит»**, чтобы это было очевидно визуально, а не только по виду чекбокса.
- У каждого варианта ответа есть вес (0–30) в одну или несколько категорий. Веса — внутренняя механика, пользователь их не видит.
- Вариант «всё в порядке / справляюсь» в каждом вопросе — **exclusive**: при его выборе остальные чекбоксы этого вопроса автоматически снимаются (нельзя одновременно отметить «справляюсь» и конкретную проблему — это взаимоисключающие ответы).
- В конце суммируются баллы по каждой категории по всем 4 вопросам ветки.
- Категория с максимальной суммой — «победитель», её сумма приводится к % через деление на теоретический максимум этой категории (максимум считается на этапе кода индивидуально для каждой категории, т.к. количество и вес вопросов, дающих в неё баллы, не одинаковы).
- Вторая по сумме категория (если её балл > 0) — идёт в строку кросс-сейла на экране результата.
- Баллы Q5 прибавляются в сумму категории «Команда» наравне с остальными вопросами — он участвует в подсчёте на общих основаниях. Дополнительно ответ на Q5 сохраняется как отдельный флаг `aiPartner: true | "maybe" | false`, который управляет текстом результата независимо от того, какая категория победила (см. «Экран результата»).

## Вопросы по веткам

### Общий вопрос Q5 (все ветки без исключения, последний перед результатом)

**«Представьте: у Вас есть цифровой сотрудник, который заменяет сразу нескольких специалистов — юриста, маркетолога, аналитика — помнит всё о Вашем бизнесе, выполняет поручения и помогает вести и масштабировать его без найма новых людей. Хотели бы такого?»**

- ☐ Да, хочу такого AI-помощника на постоянной основе → `aiPartner = true`, Команда +30
- ☐ Интересно, но сначала хочу закрыть одну конкретную задачу → `aiPartner = "maybe"`, Команда +10
- ☐ Нет, нужно решить конкретную проблему разово → `aiPartner = false`

### Развилка (только для Предприниматель и Своё)

**«У Вас обычно есть готовый поток обращений от клиентов, или чаще Вы сами ищете и предлагаете себя (холодные продажи, B2B, тендеры)?»**

- Входящие → идём в нишевую/generic ветку ниже
- Исходящие → идём в аутбаунд-ветку ниже

### Ветка: Своё (generic, входящая)

1. **Куда сейчас приходят заявки от клиентов?**
   - ☐ Только личка/директ в соцсетях, отдельной страницы нет — Сайт +25
   - ☐ Есть сайт, но на конструкторе / давно не обновлялся — Сайт +15
   - ☐ Сайт есть, но заявки всё равно чаще идут в директ, а не через форму — Сайт +10, Бот +10
   - ☐ Сайт есть и работает нормально — 0 (exclusive)
2. **Как Вы отвечаете клиентам, когда пишут вечером, в выходные или сразу много людей?**
   - ☐ Отвечаю сама/сам, когда доходят руки — Бот +25
   - ☐ Часть просто теряется, забываю ответить — Бот +25, Сайт +10
   - ☐ Есть менеджер, но не 24/7 — Бот +15
   - ☐ Отвечаю быстро, тут всё ок — 0 (exclusive)
3. **Что чаще всего отнимает время уже после того, как клиент написал?**
   - ☐ Отвечать на одни и те же вопросы про цены/условия — Бот +20
   - ☐ Собирать и обрабатывать документы/данные от клиента — Агент +25
   - ☐ Составлять отчёты, вести учёт, анализировать — Агент +20
   - ☐ Напоминать о встрече, оплате, дедлайне — Агент +15, Бот +10
   - ☐ Ничего из этого, справляюсь быстро — 0 (exclusive)
4. **Сколько у Вас процессов, которые тормозят рост, потому что Вы тянете их в одиночку?**
   - ☐ 0–1, справляюсь — 0 (exclusive)
   - ☐ 2–3, руки не доходят автоматизировать — Команда +15, Агент +10
   - ☐ 4+, хочу расти, но упираюсь в то, что не могу нанять больше людей — Команда +30

   - ☐ Есть сайт, но без формы заявки — Сайт +15
   - ☐ Сайт есть, но клиенты сначала пишут в директ с вопросом «а поможете ли мне» — Бот +10
   - ☐ Заявки приходят через сайт нормально — 0 (exclusive)
2. **Что происходит, когда человек пишет вечером с вопросом вроде «пришёл штраф, что делать»?**
   - ☐ Отвечаю сама/сам, когда есть время — Бот +25
   - ☐ Человек не дожидается ответа и обращается к другому юристу — Бот +25, Сайт +10
   - ☐ Есть помощник, но не всегда на связи — Бот +15
   - ☐ Отвечаю быстро в любое время — 0 (exclusive)
3. **Что отнимает время из этого?**
   - ☐ Собирать и структурировать детали дела от клиента вручную — Агент +25
   - ☐ Искать прецеденты и релевантную практику — Агент +20
   - ☐ Готовить документы и заключения — Агент +15
   - ☐ Ничего из этого, справляюсь — 0 (exclusive)
4. **Смогли бы Вы вести больше дел одновременно прямо сейчас?**
   - ☐ Нет, и с текущими объём работы зашкаливает — Команда +30
   - ☐ Смогла бы/смог бы, но нужен ещё один юрист/помощник — Команда +20
   - ☐ Да, процесс отлажен — 0 (exclusive)

## Экран результата

Показываем:

1. Шкала/процент по категории-победителю + персональный текст рекомендации (текст зависит от категории: Сайт → лендинг/корп.сайт 9k/19k; Бот → Сайт+AI-бот 49k; Агент/Команда → индивидуальное решение, «обсудим задачу»).
2. Одну строку кросс-сейла по второй категории («и ещё заметно, что важна X — тут тоже есть, чем помочь»), только если её балл > 0.
3. Флаг `aiPartner` меняет экран по-разному в зависимости от значения:
   - `true` — полная замена: экран показывает только AI-партнёр-вариант («Вам подойдёт AI-агент — недорогой цифровой помощник 24/7: советует, берёт часть работы на себя и подкидывает идеи для роста»), обычный текст категории-победителя не показывается. Ответ «да» на Q5 — это сильный сигнал, который перевешивает точечную рекомендацию.
   - `"maybe"` — не заменяет, а дополняет: основной результат (категория-победитель) остаётся, снизу добавляется мягкая строка: «Кстати, если позже захотите не разовое решение, а постоянного AI-помощника — это тоже можно обсудить». Человек ещё не готов к комплексному решению, показывать его как главный результат преждевременно.
   - `false` — ничего не добавляется, обычный результат без изменений.
4. CTA везде одинаковый по смыслу: **«Оставьте контакт — покажу, как это будет работать у Вас»** (не «пришлю точный расчёт» — квиз не может дать точную цифру без разговора).

## Форма и отправка

Переиспользуем существующий pipeline с главной страницы (`index.html`): тот же `<form>` c `action="https://formspree.io/f/mjgdaryr"` + тот же `fetch` на Google Apps Script URL. Никакой новой инфраструктуры приёма заявок.

Дополнительные поля, которых нет в форме на главной, добавляются в payload обоих каналов:

- `niche` — выбранная ниша (или свободный текст из поля «Своё»)
- `flow` — «входящие» / «исходящие» (если применимо)
- `quiz_answers` — текстовая расшифровка того, что отмечено на каждом вопросе (не баллы, а формулировки — чтобы читалось человеком в таблице/письме)
- `result_category`, `result_percent` — итоговая рекомендация и процент
- `ai_partner` — да/может быть/нет

Отправка — один раз, по сабмиту финальной формы. Если человек не дошёл до формы — ничего не отправляется, недозаполненные лиды не создаются.

## Размещение

Отдельная страница `quiz.html` в этом же репозитории (`my-landing`), деплоится тем же способом, что и `index.html`. Стиль — переиспользовать палитру и переменные главной страницы (тёмная тема, акцент `#4a9eff`), чтобы не выглядело как чужеродная вставка.

## Осознанно не делаем сейчас

- Не генерируем вопросы под произвольную нишу через AI на лету — нет бэкенда, дорого и ненадёжно для лид-магнита. Свободный ввод ниши идёт по generic-ветке, текст сохраняется в заявке для ручного анализа.
- Не показываем пользователю сырые баллы/веса — только % победившей категории.
- Не трекаем брошенные (недозаполненные) прохождения квиза — можно добавить позже, если появится реальная необходимость это анализировать.
- Не делаем развилку «входящие/исходящие» для узкопрофильных ниш (Салон, Стоматология, HR, Бухгалтер, Оценщик, Юрист) — там входящий поток типичен по умолчанию.
