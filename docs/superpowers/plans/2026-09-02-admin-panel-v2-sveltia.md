# Шаблон сайта с панелью на Sveltia CMS — план (v2)

Черновик от 2026-09-02. Заменяет план `2026-09-01-admin-panel-mvp.md` (тот был на
собственной панели + Next.js + Vercel + Postgres — отклонён из-за запрета Vercel на
коммерческое использование бесплатного тарифа, невозможности оплаты из РФ и большого
объёма собственной разработки с ответственностью за безопасность).

---

## Простым языком (для Лены)

**Из чего собран один сайт с панелью:**

- **сайт** — обычные готовые файлы, лежат на хостинге Beget (оплата рублями, всё в одной
  компании: хостинг + домен + почта + бесплатный SSL);
- **тексты и картинки** — лежат отдельными файлами в «главной папке» проекта на GitHub
  (бесплатный склад). Это и есть «контент в собственности» — обычные файлы, которые
  принадлежат клиенту;
- **панель** по адресу `сайт.ру/admin` — готовый бесплатный редактор **Sveltia CMS** с
  твоим логотипом. Мы его не программируем, только настраиваем;
- **«робот»** (GitHub Actions, бесплатно) — после нажатия «Опубликовать» собирает сайт
  заново и кладёт на Beget. Занимает ~1 минуту;
- **маленький вход** — наша страница логина по email и паролю, чтобы клиент **не видел
  GitHub**. Это единственный кусок, который мы пишем сами, и он небольшой.

**Что делаешь ты для нового сайта:** копируешь заготовку → заполняешь список полей
(что клиент сможет менять) → собираешь внешний вид со мной → заводишь клиенту склад на
GitHub и хостинг на Beget по чек-листу → создаёшь логин, отдаёшь доступ.

**Что делает клиент:** заходит на `сайт.ру/admin`, вводит email и пароль (GitHub не
видит), правит текст/цену/картинку/список, жмёт «Опубликовать», через минуту сайт
обновился. Ошибся → «История» → «Вернуть эту версию».

**Что мы получаем бесплатно** (в прошлом плане это надо было программировать и охранять):
история всех версий, откат, черновик→публикация, загрузка картинок.

**Честные минусы:**

1. После «Опубликовать» сайт обновляется через ~1 минуту, не мгновенно.
2. «Маскировка GitHub» работает на 90%. Технически ключ доступа к складу оказывается в
   браузере клиента — очень любопытный клиент теоретически может его достать и зайти в
   свой же склад напрямую. Вреда другим сайтам это не наносит (ключ только от его склада).
3. При настройке нового сайта на один шаг больше, чем на Vercel (подключить «робота»), —
   но это разовый рецепт по чек-листу.

**Технологии:** Eleventy (11ty) v3 — генератор статики; Sveltia CMS — панель (формат
конфига совместим с Decap CMS); Node.js 20 — маленькое приложение входа/истории на Beget;
GitHub + GitHub Actions — склад и «робот»; `@11ty/eleventy-img` — сжатие картинок при
сборке; Playwright — сквозной e2e; Vitest — юнит-тесты Node-приложения.

## Принятые решения (менять, если неверно)

1. **Язык приложения входа — Node.js**, не PHP: в песочнице есть Node (можно
   разрабатывать и тестировать локально), Beget поддерживает Node на виртуальном
   хостинге. Подтвердить поддержку Node при заведении аккаунта Beget (Задача 3.2).
2. **Склад — GitHub** (не GitLab): туда же встроен бесплатный «робот» (Actions).
   Запасной вариант — GitLab, если доступ к GitHub из РФ станет проблемой.
3. **Репозиторий заводится на аккаунт клиента** (по концепции — независимость с первого
   дня). Отдельный «бот»-аккаунт Лены добавляется в репозиторий как соавтор: от него
   берётся токен для панели и через него Лена работает как `editor`.
4. **Токен для панели — fine-grained Personal Access Token бота**, доступ только к
   одному репозиторию (contents + pull requests). Срок — 1 год, продление по
   напоминанию. Ужесточение (GitHub App, часовые токены) — после пилота.
5. **Черновик→публикация — editorial workflow Sveltia** (сохранение уходит в отдельную
   ветку, «Опубликовать» вливает в основную). Проверить связку с нашим входом рано —
   Задача 2.4.
6. **Предпросмотр в v1 — панель предпросмотра внутри Sveltia** (как получится выглядеть,
   рисуется из тех же шаблонов). Отдельный сайт-предпросмотр на поддомене — Этап 5.
7. **Хостинг — по аккаунту Beget на клиента** (тариф Blog, 420 ₽/мес, до 5 сайтов —
   для старта клиента с одним сайтом с запасом). Если клиент отдаёт хостинг Лене на
   обслуживание — можно держать несколько на одном тарифе, это уже вопрос пакета
   поддержки, не архитектуры.
8. **Сжатие картинок — при сборке** (`eleventy-img`): клиент грузит оригинал, робот
   делает webp и нужные размеры. Оригинал остаётся в складе (для лендинга за годы это
   не проблема).

## Принятые риски (осознанно, не чиним в v1)

- **Токен в браузере клиента** (см. решение 4): ограничен одним репозиторием.
- **Задержка ~1 мин** между «Опубликовать» и обновлением сайта (сборка роботом).
- **editorial workflow Sveltia** исторически капризен — поэтому проверяется отдельной
  ранней задачей (2.4); если не заработает надёжно, запасной план — одна ветка
  `draft` + кнопка «Опубликовать» вливает её в `main` (наша, в `/admin/_panel/`).
- **Счётчик символов** в Sveltia из коробки не на всех полях — если критично для
  заголовков, добавляем свой мини-виджет позже.
- **Переименование поля** после запуска сайта: тексты — обычные файлы в git, поэтому
  переименование = замена ключа в JSON + в конфиге + в шаблоне, одним коммитом, история
  остаётся читаемой. Короткая инструкция — Задача 5.4 (в прошлом плане это была
  главная нерешённая проблема; на файлах она много легче, чем на базе данных).

## Глобальные ограничения

- **Node.js 20**, пакетный менеджер `npm`.
- **Всё, что видит клиент, — на русском**: наш вход, письма, кнопки. Интерфейс самой
  Sveltia русифицируется через её локализацию (проверить полноту — Задача 1.2).
- **Машинное имя поля клиенту не показывается** — только `label` и `hint` (в Sveltia так
  по умолчанию).
- **Порядок полей в панели = порядок в `admin/config.yml`** (в Sveltia так по умолчанию).
- **Секреты** (`users.json`, токен бота, FTP-доступы) — вне веб-корня и вне git.
  В репозитории — только `*.example` образцы.
- **Тестовая стратегия** (учли прошлый провал — тесты упирались в отсутствующую БД):
  - Eleventy-сайт — тестируется локально целиком (`build` + `serve`).
  - Sveltia — локально через `@sveltia/cms` local backend (без GitHub).
  - Node-приложение входа/истории — Vitest, GitHub API мокается; один прогон против
    реального тест-репозитория при наличии токена.
  - Робот-деплой — локально проверяется только сборка; FTP-шаг — «сухой» прогон при
    заведённом Beget (Задача 3.3).
  - Сквозной e2e — на этапе пилота (Задача 6.1).
- **Коммит после каждой задачи с зелёной проверкой**, формат: `feat: …` / `test: …` /
  `chore: …` / `docs: …`.
- **Ветка разработки:** `agent/admin-panel-v2`, ответвлена от `master`. Каркас Next.js
  из ветки `agent/admin-panel-mvp` (коммит `3365bce`) не используется.

## Этап 0 — Сайт и контент в файлах

### Задача 0.1: Каркас Eleventy

**Файлы:** `package.json`, `.eleventy.js`, `src/index.njk`, `src/_includes/base.njk`,
`src/styles/site.css`, `.gitignore`

**Что делает:** рабочие команды `npm run build` (собирает `_site/`), `npm run dev`
(локальный сервер с автообновлением).

**Шаги:**
1. `git checkout master && git checkout -b agent/admin-panel-v2`.
2. Удалить файлы каркаса Next.js, если попали из прошлой ветки (их в `master` нет —
   проверить `git status`).
3. `npm init -y`; `npm i -D @11ty/eleventy@^3`.
4. `.eleventy.js`: вход `src`, выход `_site`, шаблоны Nujucks, копировать `styles` и
   `uploads` как есть.
5. `src/index.njk` + `base.njk` — минимальная страница «Привет».
6. Скрипты в `package.json`: `"build": "eleventy"`, `"dev": "eleventy --serve"`.

**Проверка:** `npm run build` → в `_site/index.html` есть «Привет». `npm run dev` →
`http://localhost:8080` отдаёт страницу.

**Коммит:** `chore: каркас Eleventy`

### Задача 1.2: `config.yml` — все типы полей и разделы

**Файлы:** `src/admin/config.yml`

**Что делает:** описывает все разделы и поля лендинга. Это и есть «схема» — для нового
сайта переписывается только этот файл.

**Соответствие типов:** текст→`string`; длинный текст→`text`; форматированный→`markdown`
(минимальный тулбар: жирный, ссылка, список); число→`number`; галочка→`boolean`;
ссылка→`string` + `pattern` на `https?://`; выбор→`select`; картинка→`image` (+ соседнее
обязательное поле `alt`); список→`list` с `fields`; группа→`object`;
переиспользуемый фрагмент (SEO) — общий кусок `fields`, вставляемый в разделы.

**Шаги:**
1. Разделы: `hero`, `services` (folder-коллекция), `prices` (list), `faq` (folder),
   `contacts`, `settings` (file), `seo` (вставляется в `settings` или отдельно).
2. Каждому полю — `label` и `hint` на русском. Проверить `pattern`-сообщения на русском.
3. ~~Условное поле: `buttonText` показывать только при `showButton: true` — через
   `condition` Sveltia.~~ **Проверено (2 сентября 2026): в Sveltia CMS условных полей
   нет** (issue [sveltia/sveltia-cms#139](https://github.com/sveltia/sveltia-cms/issues/139),
   открыт, не реализовано). Решение: `buttonText` показывается в панели всегда, с `hint`
   «учитывается, только если включена «Показывать кнопку» выше». Осознанное упрощение,
   не баг — пере­открыть, когда/если апстрим добавит `condition`.
4. Русская локализация интерфейса Sveltia: языка интерфейса нет как ключа в `config.yml` —
   это личная настройка каждого пользователя внутри самой панели (хранится в его браузере).
   Проверить визуально при первом реальном использовании и, если по умолчанию встаёт не
   русский, — переключить в настройках панели и зафиксировать в `docs/handover`.

**Проверка:** `npm run check:config` — YAML валиден, у каждого поля есть `label`/`hint`
на русском, у картинок есть обязательный `alt`. Визуальная проверка в браузере (все типы
полей рисуются и сохраняются, машинные ключи не видны, язык интерфейса) — отложена до
первого запуска с реальным браузером (вне headless-песочницы агента).

**Коммит:** `feat: список полей лендинга (все типы полей, русские подписи и подсказки)`

### Задача 1.3: Брендирование панели

**Файлы:** `src/admin/config.yml`, `src/admin/branding/logo.png` (плейсхолдер)

**Что делает:** логотип клиента в шапке панели, на экране входа и на вкладке браузера;

**Найдено при реализации (2 сентября 2026), меняет шаги 2–3 исходного плана:**

**Блокер 1 — права доступа (решён 4 сентября 2026 поддержкой Beget):**
Beget запускает каждый сайт от изолированного пользователя, который по

владельцу файла. Открыли тикет с точным текстом ошибки и `getfacl` —
техподдержка сама поправила права на сервере (детали вмешательства не
раскрыли, но результат подтверждён).

**Блокер 2 — точка входа не запускалась под Passenger (найден и решён
4 сентября 2026):** после починки прав `/health` всё равно не отвечал.
Причина — старый `server.js` запускал `http.createServer(...).listen(...)`
только под условием `import.meta.url === file://process.argv[1]` (чтобы
тесты, которые лишь импортируют `createApp`, не поднимали настоящий
сервер) — **под Apache mod_passenger это условие никогда не выполняется**,
и сервер молча не стартовал без единой ошибки в логах. Исправили —
разнесли на `server.js` (только `createApp`, без побочных эффектов) и
новый `serve.js` (безусловно поднимает сервер, слушает `127.0.0.1`) —
`serve.js` стал точкой входа и для Passenger (`PassengerStartupFile`), и
для `npm start`. Все 48 тестов остались зелёными после рефактора.

**Результат:** `https://elenamfv.beget.tech/admin/_panel/health` отвечает

## Покрытие требований концепции (CONCEPT.md р. 6)

| Требование | Где закрыто |
|---|---|
| Формат «списка полей» + пример | `admin/config.yml` (1.2) |
| Форма по списку: разделы, подписи, подсказки, проверка | Sveltia (1.2) |
| Счётчик символов на заголовках | частично Sveltia; свой виджет — риск/позже |
| Все типы полей, включая список с перетаскиванием | Sveltia `list` (1.2) |
| Картинка: загрузка + автосжатие + alt | 0.3 (сборка) + 1.2 (`image`+`alt`) |
| Автосохранение черновика | Sveltia (черновик в ветке) |
| Черновик → предпросмотр → публикация + статус | editorial workflow (2.4) |
| История версий: было/стало + откат | 4.1 |
| Экран «Общие настройки» | раздел `settings` в конфиге (1.2) |
| Вход, смена пароля, две роли | 2.3, 2.5, 4.3 |
| Не разлогинивает без причины | сессионная кука + токен бота (2.3) |
| Фирменный вид + «С чего начать» | 1.3, 4.4 |
| Экспорт контента | 4.2 |
| Сайт показывает контент, метки в вёрстке | 0.2 |
| SEO | 0.2 (`seo.json` в `<head>`) |
| Сброс кэша после публикации | робот пересобирает сайт (3.1) |
| Условные поля | не поддержаны Sveltia (1.2) — заменено подсказкой (`hint`) |
| Обход лимита загрузки | не актуально — Sveltia грузит в GitHub напрямую |
| Комплект сдачи | Этап 5 |
| Один реальный сайт, весь цикл | Этап 6 |
| Защита последнего владельца | 2.2, 4.3 |
| Независимость клиента | репозиторий и хостинг на клиента; контент — обычные файлы |
